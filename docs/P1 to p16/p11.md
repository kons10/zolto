# Zolto Phase 11 — Animation & Presentation Runtime

## Goal

Build a runtime layer that gives Zolto controlled motion, transitions, and presentation capabilities without breaking the document-first design of the language.

This phase adds visual motion, timed sequencing, and presentation behavior on top of the interactive and component systems from earlier phases.

Everything from Phases 1–10 must continue working exactly as before.

---

# Objectives

Create a complete animation and presentation system featuring:

* Animations
* Transitions
* Keyframes
* Easing
* Timelines
* Staggered motion
* Scroll-triggered motion
* Slide decks
* Speaker notes
* Presentation controls
* Scene sequencing
* Timed reveals
* Accessibility
* Performance optimization

---

# 1. Animation Directive

Implement a native animation system.

Example

```zolto id="a1n9m2"
@animate name="fadeIn" duration=300 easing="ease-out"
  opacity: 0 -> 1
  translateY: 12 -> 0
@/animate
```

Requirements

* Declarative syntax
* No arbitrary script execution
* Stable AST nodes
* Reusable animation definitions
* Renderer support
* Theme-aware motion tokens

# 3. Keyframes

Implement keyframe-based motion.

Example

```zolto id="kfr112"
@keyframes popIn
  0%   { transform: scale(0.9); opacity: 0; }

@/keyframes
```

Requirements

## Not Included

Do NOT implement:

* Plugin API
* LSP / IDE tooling
* Collaboration
* Theme engine
* Arbitrary scripting
* Full live-editor runtime
* External animation libraries as core dependencies

Those belong to later phases or optional integrations.

---

# Final Goal

At the end of Phase 11, Zolto should provide a polished motion and presentation runtime that makes documents feel alive, supports professional slide decks, and enables elegant, accessible animation without compromising the language’s declarative nature.
