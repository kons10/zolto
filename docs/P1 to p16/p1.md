You are building Phase 1 of Zolto.

Goal:
Create the Markdown-only core of Zolto first. Zolto is a strict superset of Markdown, so Phase 1 must support normal Markdown syntax before any advanced features like math, diagrams, components, layouts, or charts. Keep the system small, stable, and easy to extend later.

Phase 1 scope:
Implement only the core Markdown foundation:
- headings
- paragraphs
- horizontal rules
- blockquotes
- ordered and unordered lists
- checklist/task items
- links
- images
- inline bold, italic, code, strikethrough
- code blocks
- tables
- frontmatter
- comments
- imports
- variables
- basic custom heading IDs and classes
- footnotes and references only if they can be implemented cleanly without adding advanced domain logic

Do NOT implement in Phase 1:
- math
- diagrams
- charts
- vector graphics
- layout blocks
- component system
- tabs
- cards
- accordions
- quiz/flashcard blocks
- animation
- advanced directives beyond what is needed for plain Markdown compatibility

Architecture requirements:
- Build a tokenizer, parser, AST factory, and HTML renderer.
- Parse source into a structured AST first, then render from AST.
- Keep node shapes stable and consistent.
- Use `null` for optional fields instead of missing keys.
- Use arrays for all list-like fields.
- Keep inline parsing separate from block parsing.
- Make the renderer stateless and deterministic.
- Keep the codebase modular and easy to expand in later phases.

Implementation requirements:
- Support `.zl` files as the source format.
- Preserve Markdown readability.
- Make plain Markdown documents valid Zolto documents.
- Ensure parser error handling is clear and helpful.
- Add basic validation for malformed Markdown structures.
- Add tests for every supported block and inline feature.
- Add sample input/output fixtures.
- Keep the implementation clean and maintainable.

Suggested file structure:
- tokenizer
- lexer
- parser
- ast factory
- inline parser
- validator
- renderer
- tests
- examples
- docs

Output requirements:
- Generate the Phase 1 engine with working parsing and rendering.
- Provide a minimal but complete Markdown subset.
- Include sample `.zl` files and rendered HTML examples.
- Write code in small modules, not one giant file.
- Make the design ready for Phase 2 expansion.

Quality target:
Phase 1 should feel like a solid Markdown engine with Zolto naming and structure, not a half-finished prototype. It must be reliable enough to become the foundation for the rest of Zolto.
