# Zolto Phase 9 — Component, Template & Macro System

## Goal

Build a reusable abstraction layer for Zolto so authors can define once and reuse everywhere.

This phase makes Zolto more scalable, more maintainable, and more powerful for real-world documents, apps, dashboards, design systems, and reusable content blocks.

Everything from Phases 1–8 must continue working exactly as before.

---

# Objectives

Create a complete reusable content system featuring:

* Custom components
* Templates
* Macros
* Props
* Slots
* Slot forwarding
* Composition
* Conditional rendering
* Loop rendering
* Registry system
* Reusable patterns
* Safe expansion
* Validation
* High performance

---

# 1. Component System

Implement custom components.

Example

```zolto
@component Card title="" subtitle="" variant="default"
  @card variant={variant}
    ### {title}
    {subtitle}
    @slot default
    @/slot
  @/card
@/component
```

Use

```zolto
<Card title="Welcome" subtitle="Hello world" variant="primary">
  This is the body.
</Card>
```

Requirements

* Named components
* PascalCase names
* Default props
* Use-site props
* Nested components
* Recursive protection
* Composition support
* Clear error messages
* Stable AST nodes
* Efficient rendering

---

# 2. Slots

Implement slots for flexible content injection.

Support

* Default slot
* Named slots
* Multiple slots
* Fallback content
* Slot forwarding
* Nested slot content
* Empty slot handling

Example

```zolto
@component Panel title=""
  @slot header
    ### {title}
  @/slot

  @slot default
    No content provided.
  @/slot

  @slot footer
    ---
    Footer area
  @/slot
@/component
```

Requirements

* Slot mapping
* Slot fallback resolution
* Safe nested content
* Validation of unknown slots
* Ordered slot insertion
* Renderer support

# 5. Macros

Implement macros for small reusable transformations.

Support

* Text macros
* Inline macros
* Block macros
* Parameterized macros
* Macro expansion
* Safe recursion limits
* Macro validation

Example

```zolto
@macro note text
[info]
{text}
[/info]
@/macro
```

Use

```zolto
@note "This is an important note."
```

Requirements

* Expand before rendering
* Prevent infinite recursion
* Support arguments
* Support defaults
* Support nested macro calls
* Keep macro expansion predictable

# 6. Conditionals

Implement conditional rendering for templates and components.

Support

* `if`
* `else`
* `elseif`
* Boolean expressions
* Equality checks
* Presence checks
* Negation

Example

```zolto
{#if featured}
  @badge tone="primary" Featured
{/if}
```

Requirements

* Safe expression evaluation
* No arbitrary code execution
* Deterministic output
* Clear diagnostics
* AST support

# 7. Loops

Support

* `each`
* Lists
* Arrays
* Item indexing
* Keyed iteration
* Nested loops

Example

    {item.body}

* Loop scope handling
* Nested loops
* Loop validation
* Efficient rendering

# 10. Renderer

Build a dedicated component/template/macro renderer.

Requirements

* Resolve definitions before rendering
* Render with stable output
* Support nested components
* Support slot injection
* Apply prop defaults
* Prevent infinite recursion
* Maintain context correctly
* Work with Markdown, Math, Diagram, Chart, Vector, and Layout nodes

---

# 11. AST

Create dedicated AST node types for:

* ComponentDef
* ComponentUse
* TemplateDef
* TemplateUse
* SlotDef
* SlotOutlet
* MacroDef
* MacroUse
* ConditionalBlock
* LoopBlock
* PropList

All nodes must:

* Use stable object shapes
* Use `null` instead of missing values
* Use arrays for collections
* Be safe for future extension

---

# 12. Validation

Detect and report:

* Unknown components
* Duplicate component names
* Missing required props
* Invalid prop types
* Undefined slots
* Duplicate slot names
* Recursive component calls
* Recursive macro expansion
* Invalid template use
* Invalid conditional syntax
* Invalid loop syntax

Diagnostics must be clear, actionable, and location-aware.

* Incremental re-rendering

## Not Included

Do NOT implement:

* Plugin API
* IDE/LSP
* Collaboration
* Theme engine
* Animation runtime
* Interactive widgets
* Presentation transitions

These belong to later phases.

# Final Goal

At the end of Phase 9, Zolto should provide a complete reusable abstraction system that lets authors build their own design systems, document systems, and content libraries with components, templates, macros, props, and slots while remaining fully compatible with the rest of the language.
